リポジトリの中身を確認しました。Search-Immersion は「Google検索画面や新タブを Nest Hub 風スマートディスプレイに変える」Chrome拡張で、時計・天気・ニュース・TODO・タイマーなどをすりガラス風UIで表示し、テーマ切替やZenモード（集中モード）も備えています。素のJavaScript + CSSで作られていて、外部APIは Open-Meteo（天気）・Unsplash（画像）・RSSフィードあたりを使っていますね。

結論から言うと、**「まず要件をはっきりさせる」という方針は正しいです**。ただ、個人学習プロジェクトでは要件定義が完璧である必要はなく、「MVPの範囲が決まる」程度で十分です。要件を詰めすぎると学習が始まらないので、ここはほどほどに。

## 要件を固めるべき観点（6つ）

1. **使う場面・端末** — 常時表示のディスプレイ（Nest Hub的運用）か、ブラウザで開くだけか。前者なら焼き付き防止や大画面レイアウトが要件に入ります
2. **モジュールの優先順位** — 時計・天気・ニュース・TODO・検索・タイマー・ブックマーク…どれが「本当に欲しい」か。最初は3つ以内に絞るのがおすすめです
3. **データ永続化** — TODOや設定を保存する必要があるか。自分専用・1端末なら `localStorage` で十分で、サーバーやDBは不要です
4. **外部連携** — 天気・ニュース・検索サジェストなど。ここだけは技術的な制約が絡むので後述します
5. **デザインの方向性** — 参考リポジトリのどの要素を真似たいか（ガラス風カード、テーマ切替、Zenモード）
6. **学びの目標** — これが実は最重要です。「UI/デザインを学びたい」「API連携を学びたい」「バックエンドやデプロイを学びたい」で技術選定が変わります

## 技術スタックの提案

学習目的に応じて、こんな分け方が考えられます。

| 学びたいこと | おすすめ構成 |
|---|---|
| HTML/CSS/JSの基礎 | 素のHTML+CSS+JS。`python -m http.server` などでローカル起動 |
| モダンなフロントエンド開発 | Vite + Vanilla JS か React。ビルドや開発サーバーの体験が学べる |
| バックエンド・運用 | フロント + Node/Express や Python/FastAPI でAPIを自前実装 |

個人的なおすすめは **「最初は Vite + 素のJavaScript」** です。参考リポジトリと同じ流儀なのでソースを読む参考にもなりますし、フレームワークの学習と要件実装を同時にやると混乱しがちです。後から React やバックエンドに足を広げられます。

## 見落としがちなポイント：CORS

普通のWebページ（ブラウザから直接fetch）で外部APIを呼ぶ場合、**CORS（クロスオリジン制約）** が効いてきます。天気の Open-Meteo はCORS対応で問題なく動きますが、**ニュースのRSSや検索サジェストAPIはブラウザ直呼びだとブロックされることが多い**です。回避策は ①CORS対応の変換サービス（rss2json 等）を挟む ②自分の小さなバックエンドを作る（これ自体が良い学習になる）③Cloudflare Workers などを使う。この制約を知っているかどうかで、要件に「自前APIを持つか」が入ってくるかが変わります。
